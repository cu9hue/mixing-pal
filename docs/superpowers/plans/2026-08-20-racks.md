# Racks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the model see inside a Rack — list a Drum Rack's pads and their devices, and read the parameters of any device nested inside one.

**Architecture:** A device stops being `(track, device_index)` and becomes `(track, path)`, where the path alternates device and chain indices and travels the wire as one dotted string. New Remote Script handlers resolve that path and list a rack's chains; the listing and the resolution share one enumeration function, so a chain index cannot mean two different things. The handler, not the client, decides how many chains fit in a datagram.

**Tech Stack:** Rust (Tauri backend, `rosc`, `tokio`), Python 3 (Live Remote Script, stdlib only), TypeScript (digest).

**Spec:** `docs/superpowers/specs/2026-08-15-ableton-copilot-design.md` — the **Racks** section, which supersedes the "Devices inside Racks are not listed" limit in **Devices**. Read both.

## Global Constraints

- **Read-only.** This app never writes to the producer's set. No `set` address is added, called, or registered.
- **`MAX_DATAGRAM` is 9216 bytes** (`src-tauri/src/osc/budget.rs:3`), with `HEADER_SLACK` 256. Exceeding it makes `sendto` raise inside Live and the client receives **nothing at all** — silence, not truncation, indistinguishable from a lost reply.
- **`arity.rs` is a literal exhaustive match.** Never compute an arity, never add a prefix guard. Every new address gets its own line and its own row in `classifies_every_endpoint_the_design_uses`.
- **Fail closed.** A reply whose shape does not match produces no value. Never decode a misaligned prefix, never guess which elements are which.
- **Empty is not missing.** A rack with no chains, a chain with no devices, and a device with no parameters all return an empty list with `missing_reason: null`.
- **Fence every set-derived string** through `crate::tools::fence::fence` before it can reach a prompt. Chain names, pad names, device names, parameter names and formatted values are all producer- or plugin-controlled text.
- **Nothing is polled.** No `PollKind`, no mirror storage, nothing added to the standing context block. Every address here is a live query behind a tool.
- **`std::sync::Mutex` guards are `!Send`** on purpose. Never hold one across an `.await`; scope it to a block.
- **Verification commands must use `set -o pipefail`** before any `cd`, and match `test result: ok\.` exactly. `cargo test | tee log; grep ...` takes `grep`'s exit status and `^test result` matches `FAILED` as happily as `ok`.
- **RTK rewrites `cargo test` output** in some shells to a one-line summary. If `grep -E "^test result: ok\."` finds nothing, read the pass/fail counts rather than concluding failure.

```rust
use serde_json::Value;

/// The path from a track to one device: alternating device and chain
/// indices, always of odd length.
///
/// `[d]` is a top-level device. `[d, c, d]` is a device in chain `c` of the
/// rack at `d`. Every step into a rack costs a chain index and a device
/// index together, which is why the length is odd — an even-length path
/// names a chain, and a chain is not a thing this app reads parameters from.
///
/// Travels the wire as ONE dotted string, and that is the load-bearing
/// choice. A run of int arguments would make each address's key arity a
/// function of the request, and `osc/arity.rs` is a literal exhaustive match
/// precisely so that no arity is ever computed. One string argument keeps
/// the ranged addresses at a constant `Args(3)`; `RequestTable::key_of`
/// already encodes `OscType::String`, so single-flight keying, cancellation
/// and mis-attributed-reply rejection all work unchanged.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DevicePath(Vec<u32>);

/// Four racks deep, and a guard rather than a product limit.
///
/// Path resolution runs inside Live's callback, on the thread that also has
/// to service audio. An unbounded walk driven by a malformed path is not a
/// cost this app gets to impose on a producer's session, so the refusal
/// happens here, before anything reaches the wire.
pub const MAX_PATH_LEN: usize = 9;

impl DevicePath {
    pub fn parse(raw: Option<&Value>) -> Option<Self> {
        let items = raw?.as_array()?;
        if items.is_empty() || items.len() > MAX_PATH_LEN || items.len() % 2 == 0 {
            return None;
        }
        let mut out = Vec::with_capacity(items.len());
        for item in items {
            out.push(element(item)?);
        }
        Some(DevicePath(out))
    }

    /// The dotted form `copilot/rack_paths.py::parse_path` reads back.
    pub fn wire(&self) -> String {
        self.0
            .iter()
            .map(u32::to_string)
            .collect::<Vec<_>>()
            .join(".")
    }
}

/// One path index.
///
/// Mirrors `int_arg`'s float tolerance — real providers emit `1.0` for an
/// integer field — and adds the two rules a path index needs on top. A
/// negative index is refused because Python slices from the END on one, so
/// it would resolve silently to a real but different device. An index past
/// `i32::MAX` is refused because every index is narrowed to `i32`
/// downstream and `as i32` wraps rather than saturates.
fn element(v: &Value) -> Option<u32> {
    let n = match v.as_i64() {
        Some(i) => i,
        None => {
            let f = v.as_f64()?;
            if !f.is_finite() || f.fract() != 0.0 {
                return None;
            }
            f as i64
        }
    };
    (0..=i64::from(i32::MAX)).contains(&n).then_some(n as u32)
}
```

```python
        return [
            (FakeChain(name, [FakeDevice("Dev%d" % d) for d in range(devices_each)]),

        self.assertEqual(record[5], rack_paths.MAX_DEVICES_PER_CHAIN)
        self.assertEqual(len(record), 6 + rack_paths.MAX_DEVICES_PER_CHAIN)

        self.assertEqual(len(rack_paths.build_window(self.entries(50), 0, 8)), 8)

        # sender, which is the only side that knows the sizes, has to stop.
        fat = self.entries(40, devices_each=32)

        self.assertLess(len(window), 40)

        # loop makes no progress and spins until MAX_WINDOWS.

        self.assertEqual(len(window), 1)

        long_name = "x" * 5000

    def test_a_start_past_the_end_returns_nothing_rather_than_wrapping(self):
```

```python
"""Path resolution and chain enumeration for Racks.

Deliberately free of Live imports. Everything under `abletonosc/` reaches
`ableton.v2.control_surface`, which exists only inside the application, so a
module that imports a handler cannot be tested anywhere else. `rack.py` holds
the OSC handlers; this file holds the logic that can be wrong, and
`remote-script/tests/test_rack_paths.py` exercises it with fakes.
"""

#--------------------------------------------------------------------------------
# Mirrors MAX_DATAGRAM - HEADER_SLACK in src-tauri/src/osc/budget.rs, and is
# pinned from the Rust side by rack_byte_ceiling_matches_the_budget. A handler
# that overfills a datagram makes sendto raise inside Live, and the client then
# receives NOTHING AT ALL -- silence, not truncation, indistinguishable from a
# lost reply. So this number is load-bearing and duplicated across a language
# boundary, which is exactly what the pin is for.
#--------------------------------------------------------------------------------
MAX_REPLY_BYTES = 8960

# Matches src-tauri/src/tools/path.rs::MAX_PATH_LEN. The client refuses a
# longer path before sending it; this is the second half of the same guard,
# because resolution runs on Live's callback thread.
MAX_PATH_LEN = 9

# Device names carried per chain. A chain with more reports the true count and
# a shorter list; a listing is for orientation, and the model drills in with
# get_device_params once it knows where to look.
MAX_DEVICES_PER_CHAIN = 32

# Caps every name on the wire. The Rust side fences to 120 characters anyway,
# so nothing real is lost, and it bounds the worst-case record: with the name
# list emptied, six fixed fields plus a capped name is far inside one datagram.
# That is what makes shrink_to_fit terminate with a record that always fits.
NAME_CAP = 200


def parse_path(raw):
    """"0.4.1" -> [0, 4, 1]. None for anything malformed.

    Refuses even lengths (a path names a device, and every step into a rack
    costs a chain index and a device index together), anything past
    MAX_PATH_LEN, and anything that is not an ASCII non-negative integer.
    int() would happily accept "-1" and Python slices from the END on a
    negative index, which resolves silently to a real but different device;
    it also accepts non-ASCII digits, which this app never generates.
    """
    parts = str(raw).split(".")
    if len(parts) > MAX_PATH_LEN or len(parts) % 2 == 0:
        return None
    out = []
    for part in parts:
        if not part or not part.isascii() or not part.isdigit():
            return None
        out.append(int(part))
    return out


def chains_of(device):
    """Every chain in a rack, as (chain, note, name, mute, solo).

    Listing and resolution BOTH go through this, and that is the point. A
    chain index has to mean the same chain when the model reads a listing and
    when it sends that index back inside a path.

    A Drum Rack is where this goes wrong. Its pad note lives on DrumPad, not
    on Chain, so the obvious implementation lists from `drum_pads` and
    resolves through `chains`, pairing the two by position. That pairing is an
    assumption about an ordering the LOM does not promise, and when it is
    wrong it is wrong silently: every pad labelled with its neighbour's note,
    inside an answer that looks complete. Enumerating pads on both sides
    removes the assumption instead of testing it.

    A device that is not a rack yields [] rather than raising, so "not a rack"
    reaches the client as an answer rather than as silence.
    """
    if getattr(device, "can_have_drum_pads", False):
        return [(pad.chains[0], pad.note, pad.name, pad.mute, pad.solo)
                for pad in device.drum_pads if len(pad.chains) > 0]
    return [(chain, -1, chain.name, chain.mute, chain.solo)
            for chain in getattr(device, "chains", [])]


def resolve(track, path):
    """track.devices[path[0]], then chain/device pairs to the end.

    Raises IndexError past the end of any list, which AbletonOSC turns into no
    reply at all -- byte-identical to a lost datagram, exactly as the
    top-level device addresses already behave.
    """
    device = track.devices[path[0]]
    for i in range(1, len(path), 2):
        chain = chains_of(device)[path[i]][0]
        device = chain.devices[path[i + 1]]
    return device


def osc_string_bytes(text):
    """An OSC string pads to a multiple of 4 with at least one NUL, plus one
    byte of type tag."""
    return 4 * ((len(text) // 4) + 1) + 1


def record_bytes(record):
    """Serialised size of one chain record, type tags included."""
    return sum(osc_string_bytes(f) if isinstance(f, str) else 5 for f in record)


def chain_record(entry, max_names=MAX_DEVICES_PER_CHAIN):
    """(name, note, mute, solo, total_devices, reported_devices, *names).

    Six fixed fields, then exactly `reported_devices` names. The record
    announces how many names it actually carries -- not how many the chain
    has -- so the decoder can walk a stream of variable-length records with no
    separator, and so a record cut back to fit a datagram stays readable.
    `total_devices` still reports the truth.
    """
    chain, note, name, mute, solo = entry
    devices = list(chain.devices)
    names = [str(d.name)[:NAME_CAP] for d in devices[:max(0, max_names)]]
    return (str(name)[:NAME_CAP], int(note), int(bool(mute)), int(bool(solo)),
            len(devices), len(names)) + tuple(names)


def shrink_to_fit(entry, budget):
    """Halve a record's device-name list until it fits.

    Bottoms out at no names at all, which still reports the chain's own name
    and its true device count -- and, because NAME_CAP bounds every string,
    that floor is guaranteed to fit inside one datagram.
    """
    max_names = MAX_DEVICES_PER_CHAIN
    record = chain_record(entry, max_names)
    while max_names > 0 and record_bytes(record) > budget:
        max_names //= 2
        record = chain_record(entry, max_names)
    return record


def build_window(entries, start, span, budget=MAX_REPLY_BYTES):
    """Records from entries[start:], at most `span` and at most what fits.

    The HANDLER owns the window, not the client. Parameters are uniform enough
    for a client to budget -- 64 bytes each, 140 to a datagram. Chains are
    not: a four-device chain is about 340 bytes and a thirty-two-device chain
    about 2100. A client-side window sized for the first sends twenty-three of
    the second, serialises to roughly 48 KB, and Live's sendto raises so the
    client receives nothing at all. Only the sender knows the sizes.

    A single chain too large to fit alone is cut back rather than dropped, so
    every reply carries at least one record and the client's paging loop
    always makes progress.
    """
    records = []
    used = 0
    for entry in entries[max(0, start):max(0, start) + max(0, span)]:
        record = chain_record(entry)
        size = record_bytes(record)
        if used + size > budget:
            if records:
                break
            record = shrink_to_fit(entry, budget)
            size = record_bytes(record)
        records.append(record)
        used += size
    return records
```

```python
from typing import Tuple, Any
from ..abletonosc.handler import AbletonOSCHandler
from .rack_paths import build_window, chains_of, parse_path, resolve


class RackHandler(AbletonOSCHandler):
    """Opens Racks.

    `track.devices` is top-level only, so without this a loaded Drum Rack is
    one device named "Drum Rack" and the compressor on the kick pad does not
    exist as far as the app is concerned. Two addresses: list a rack's
    chains, and identify any device by path.

    Returning None sends no reply at all (see `osc_server.process_message`'s
    `if rv is not None`), which is the same thing a raise inside a handler
    produces. Both are byte-identical to a lost datagram from the client's
    side, and that equivalence is documented rather than worked around.
    """

    def __init__(self, manager):
        super().__init__(manager)
        self.class_identifier = "rack"

    def init_api(self):
        def device_for(params):
            """(device, raw_path) or (None, raw_path) for a path this script
            refuses to walk."""
            raw_path = str(params[1])
            path = parse_path(raw_path)
            if path is None:
                return None, raw_path
            return resolve(self.song.tracks[int(params[0])], path), raw_path

        def rack_chains(params: Tuple[Any]):
            device, raw_path = device_for(params)
            if device is None:
                return None
            track_index = int(params[0])
            start, span = max(0, int(params[2])), int(params[3])
            entries = chains_of(device)
            records = build_window(entries, start, span)
            flat = [field for record in records for field in record]
            # can_have_chains rides along so that two different answers stay
            # different: a device with no chains because it is an EQ, and a
            # Rack with nothing loaded in it, both list zero chains, and only
            # the first is a model error. "This rack is empty" is a real
            # observation about a set.
            return (track_index, raw_path, start, len(entries),
                    int(bool(getattr(device, "can_have_chains", False))), *flat)

        def device_identity(params: Tuple[Any]):
            device, raw_path = device_for(params)
            if device is None:
                return None
            return (int(params[0]), raw_path,
                    str(device.name), len(device.parameters))

        self.osc_server.add_handler(
            "/live/copilot/get/rack/chains", rack_chains)
        self.osc_server.add_handler(
            "/live/copilot/get/device/identity", device_identity)
```

```python
from typing import Tuple, Any
from ..abletonosc.handler import AbletonOSCHandler
from .rack_paths import parse_path, resolve


class DeviceRangeHandler(AbletonOSCHandler):
    """Upstream returns every parameter in one datagram. An Instrument Rack can
    exceed 1000 parameters, which blows past the 9216-byte macOS UDP cap and
    makes sendto raise, so the client receives nothing at all. This mirrors the
    ranged form that clip note queries already have.

    Since wire version 3 the device is named by a dotted path rather than a
    top-level index, so these addresses reach inside Racks. The reply echoes
    the path string in the position the device index used to occupy, which
    leaves the keying at KeyArity::Args(3) -- see src-tauri/src/osc/arity.rs.
    """

    def __init__(self, manager):
        super().__init__(manager)
        self.class_identifier = "device_range"

    def init_api(self):
        def window_for(params):
            """(track_index, raw_path, start, window) or None.

            Clamp before slicing: Python treats a negative stop as "from the
            end," not "empty," so a negative span (or start) would otherwise
            return far more than the caller asked for and blow past the
            datagram cap this ranged form exists to avoid.
            """
            track_index = int(params[0])
            raw_path = str(params[1])
            start, span = max(0, int(params[2])), max(0, int(params[3]))
            path = parse_path(raw_path)
            if path is None:
                return None
            device = resolve(self.song.tracks[track_index], path)
            window = list(device.parameters)[start:start + span]
            return track_index, raw_path, start, window

        def ranged(project):
            def handler(params: Tuple[Any]):
                got = window_for(params)
                if got is None:
                    return None
                track_index, raw_path, start, window = got
                return (track_index, raw_path, start,
                        *[project(p) for p in window])
            return handler

        self.osc_server.add_handler(
            "/live/device/get/parameters/value_range",
            ranged(lambda p: p.value))
        self.osc_server.add_handler(
            "/live/device/get/parameters/name_range",
            ranged(lambda p: p.name))
        self.osc_server.add_handler(
            "/live/device/get/parameters/value_string_range",
            ranged(lambda p: p.str_for_value(p.value)))
```

```rust
use crate::osc::query::{LiveQuery, QueryError};
use crate::tools::device_params::device_identity;
use crate::tools::fence::fence;
use crate::tools::path::DevicePath;
use rosc::OscType;
use serde::Serialize;
use std::time::Duration;

/// Deliberately equal to `clip_notes::QUERY_TIMEOUT`; see that constant.
pub const QUERY_TIMEOUT: Duration = Duration::from_secs(2);

/// A prompt-token cap, NOT a datagram cap — which is why it lives here and
/// not in `osc/budget.rs`. A Drum Rack has 128 pads and a fully loaded one
/// is legal, but a working kit runs eight to twenty-four. Past this the
/// tail is reported as a truncation marker rather than spent as several
/// thousand tokens of pad names.
pub const MAX_CHAINS: usize = 64;

/// Chains asked for per request. The handler returns at most this many and
/// at most as many as fit, so this is a ceiling rather than a promise.
const REQUEST_SPAN: usize = 32;

/// Bounds the paging loop so a Live that is simply not answering costs a
/// fixed number of round trips. Same constant `device_params` uses, and for
/// the same reason.
const MAX_WINDOWS: usize = crate::tools::clip_notes::MAX_WINDOWS;

#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct RackChain {
    /// The index to send back inside a path. Counts from the window start,
    /// not from zero, because the model uses it to address this chain.
    pub index: usize,
    /// Fenced. A pad name is producer-typed text.
    pub name: String,
    /// The MIDI note of a drum pad. `None` for every other kind of rack,
    /// where the wire carries -1 — rendering that as a note would put a pad
    /// number on an Audio Effect Rack chain.
    pub note: Option<i32>,
    pub muted: bool,
    pub soloed: bool,
    /// Fenced device names, in chain order.
    pub devices: Vec<String>,
    /// The chain's real device count, which exceeds `devices.len()` when the
    /// handler cut the list back to fit one datagram.
    pub total_devices: usize,
}

#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct RackContents {
    pub chains: Vec<RackChain>,
    /// Every chain the rack has, even when `chains` holds fewer.
    pub total_chains: usize,
    /// Whether the addressed device is a Rack at all. An EQ and an empty
    /// Rack both list zero chains, and only the first is a model error.
    pub is_rack: bool,
    pub truncated: bool,
    pub missing_reason: Option<String>,
}

fn int_at(reply: &[OscType], i: usize) -> Option<i32> {
    match reply.get(i)? {
        OscType::Int(v) => Some(*v),
        _ => None,
    }
}

fn str_at(reply: &[OscType], i: usize) -> Option<String> {
    match reply.get(i)? {
        OscType::String(s) => Some(fence(s)),
        _ => None,
    }
}

/// Decodes `(track, path, start, total_chains, can_have_chains, *records)`.
///
/// Each record is `name, note, mute, solo, total_devices, reported_devices`
/// followed by exactly `reported_devices` names, so a record announces its
/// own length and a stream of variable-length records needs no separator.
///
/// Fails closed on anything that does not line up. A record claiming more
/// names than the reply can hold means the stream was truncated in transit
/// or forged; either way every following byte becomes unattributable, so the
/// whole window is refused rather than yielding the prefix. Half a rack
/// presented as a whole one is worse than no rack at all.
///
/// The `expect_start` check is defence in depth, not the thing that catches
/// a mis-attributed reply: this address is `KeyArity::Args(3)`, so a reply
/// echoing a different start matches no pending entry and
/// `RequestTable::resolve` drops it first.
fn decode_window(
    reply: &[OscType],
    expect_start: usize,
) -> Option<(usize, bool, Vec<RackChain>)> {
    if usize::try_from(int_at(reply, 2)?).ok()? != expect_start {
        return None;
    }
    let total_chains = usize::try_from(int_at(reply, 3)?).ok()?;
    let is_rack = int_at(reply, 4)? != 0;

    let mut chains = Vec::new();
    let mut i = 5;
    let mut index = expect_start;
    while i < reply.len() {
        let name = str_at(reply, i)?;
        let note = int_at(reply, i + 1)?;
        let muted = int_at(reply, i + 2)? != 0;
        let soloed = int_at(reply, i + 3)? != 0;
        let total_devices = usize::try_from(int_at(reply, i + 4)?).ok()?;
        let reported = usize::try_from(int_at(reply, i + 5)?).ok()?;
        i += 6;
        if reported > reply.len().saturating_sub(i) {
            return None;
        }
        let mut devices = Vec::with_capacity(reported);
        for k in 0..reported {
            devices.push(str_at(reply, i + k)?);
        }
        i += reported;
        chains.push(RackChain {
            index,
            name,
            note: (note >= 0).then_some(note),
            muted,
            soloed,
            devices,
            total_devices,
        });
        index += 1;
    }
    Some((total_chains, is_rack, chains))
}
```

- [ ] **Step 5: Write the paging loop**

```rust
/// Lists one rack's chains, paged.
///
/// There is no halve-and-retry here, unlike every other paged read in this
/// codebase, and that is a consequence of the handler owning the window:
/// `rack_paths.build_window` stops filling before `MAX_DATAGRAM`, so an
/// oversized reply cannot happen and a `NoReply` is never "the datagram was
/// too big". What is left is a genuinely lost reply, or a path that resolves
/// to nothing — and halving a span answers neither.
pub async fn get_rack_contents(
    q: &LiveQuery,
    track: i32,
    path: &DevicePath,
    timeout: Duration,
) -> Result<RackContents, QueryError> {
    // Same bracket the parameter read uses. No reply is also how "there is
    // no device at that path" arrives: the Remote Script raises inside Live
    // and sends nothing, byte-identical to a lost datagram.
    let Some(before) = device_identity(q, track, path, timeout).await else {
        return Err(QueryError::NoReply);
    };

    let mut chains: Vec<RackChain> = Vec::new();
    let mut total_chains = 0usize;
    let mut is_rack = false;
    let mut missing_reason: Option<String> = None;
    let mut windows = 0usize;
    let mut start = 0usize;
    let mut first = true;

    loop {
        if windows >= MAX_WINDOWS {
            missing_reason = Some("too_large".to_string());
            break;
        }
        windows += 1;
        let span = REQUEST_SPAN.min(MAX_CHAINS.saturating_sub(chains.len()));
        if span == 0 {
            break;
        }

        let reply = match q
            .query(
                "/live/copilot/get/rack/chains",
                vec![
                    OscType::Int(track),
                    OscType::String(path.wire()),
                    OscType::Int(start as i32),
                    OscType::Int(span as i32),
                ],
                timeout,
            )
            .await
        {
            Ok(r) => r,
            // Nothing at all came back for the first window: the path names
            // no device, or Live did not answer. Reporting an empty rack
            // here would turn a failed read into a confident "there is
            // nothing loaded in this rack".
            Err(QueryError::NoReply) if first => return Err(QueryError::NoReply),
            Err(QueryError::NoReply) => {
                missing_reason = Some("no_reply".to_string());
                break;
            }
            Err(e) => return Err(e),
        };

        let Some((reply_total, reply_is_rack, window)) = decode_window(&reply, start) else {
            missing_reason = Some("malformed_reply".to_string());
            break;
        };

        if first {
            total_chains = reply_total;
            is_rack = reply_is_rack;
            first = false;
        } else if reply_total != total_chains {
            chains.clear();
            missing_reason = Some("topology_changed".to_string());
            break;
        }

        // The handler emits at least one record whenever records remain, so
        // an empty window means the list is finished. Breaking on it is also
        // what guarantees this loop terminates if that ever stops holding.
        if window.is_empty() {
            break;
        }
        start += window.len();
        chains.extend(window);
        if start >= total_chains {
            break;
        }
    }

    let mut truncated = total_chains > chains.len();

    // The listing was read across several seconds while the producer was, by
    // definition, working in Live. `device_identity` returns the same pair
    // the parameter read brackets on, and it cannot tell two same-named
    // devices with the same parameter count apart — recorded in the spec's
    // Known limits, not papered over here.
    match device_identity(q, track, path, timeout).await {
        Some(after) if after == before => {}
        Some(_) => {
            chains.clear();
            truncated = false;
            missing_reason = Some("topology_changed".to_string());
        }
        // Not observed at all — no reply, a busy address, a transport
        // failure, a reply the decoder refused. This is NOT "probably
        // nothing changed": deleting the very rack being read lands here
        // too, because the now-out-of-range path answers nothing.
        None => {
            chains.clear();
            truncated = false;
            missing_reason = Some("device_identity_unverified".to_string());
        }
    }

    Ok(RackContents {
        chains,
        total_chains,
        is_rack,
        truncated,
```

```rust
/// Marks a Rack in the chain map.
///
/// Sits OUTSIDE the fence, not inside it: everything between the guillemets
/// is producer-controlled text, so a marker inside would be a marker a
/// device could give itself by being renamed. Outside, it cannot be forged.
///
/// A suffix rather than a structured field, because this call is the one the
/// model is expected to make routinely and every device on every track pays
/// for its shape. `[{ "name": "...", "rack": true }]` triples the tokens of
/// the whole-set answer to carry a flag that is false for most devices.
const RACK_SUFFIX: &str = " [rack]";

/// `/live/track/get/devices/can_have_chains` replies `(track, *flags)`.
///
/// Accepts both encodings of a flag. `pythonosc` serialises a Python bool
/// with the OSC `T`/`F` type tags, and neither that nor an int is ambiguous
/// about what it means. Accepting only the wrong one would lose the whole
/// feature silently, on a detail no test outside Live can settle.
fn decode_flags(reply: &[OscType]) -> Option<Vec<bool>> {
    let mut out = Vec::with_capacity(reply.len().saturating_sub(1));
    for arg in reply.get(1..)? {
        match arg {
            OscType::Bool(b) => out.push(*b),
            OscType::Int(i) => out.push(*i != 0),
            _ => return None,
        }
    }
    Some(out)
}

/// Appends the marker to every device the flags call a Rack. Returns whether
/// it marked anything at all.
///
/// Refuses a flag list of a different length rather than zipping to the
/// shorter one: the two replies are separate datagrams and can disagree if a
/// device is added between them, and a misaligned zip marks the wrong
/// devices — sending the model into an EQ looking for drum pads while the
/// real Drum Rack goes unmarked.
fn mark_racks(devices: &mut [String], flags: &[bool]) -> bool {
    if devices.len() != flags.len() {
        return false;
    }
    for (device, is_rack) in devices.iter_mut().zip(flags) {
        if *is_rack {
            device.push_str(RACK_SUFFIX);
        }
    }
    true
}
```
