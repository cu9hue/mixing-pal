# Goal Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make craft scenario five (same set, two goals) a test that can go green with a stochastic model, by making a choice question a choice in the prompt, grading the stated decision and its tie to the goal, and splitting the scenario into a temperature-zero gate and a default-temperature report.

**Architecture:** The prompt's "What a good answer is" section gains one clause: a choice question gets one side, the way the GOAL pushed, and one move on that side. The eval harness gains a temperature seam (`ask_with`) built on the existing `build_body` and `complete_with_body`. `craft.rs` grades three properties on the goal scenario (decision keep, decision change, decision tied to the goal) and runs two tests: a gate at temperature 0 with one run per arm whose decisions must differ, and a report at the app's sampling with three runs per arm that asserts only that every answer decides and ties the decision to the goal.

**Tech Stack:** Rust (tokio, reqwest, serde_json, wiremock 0.6 in dev-deps), cargo feature `evals`, the fake Live over OSC in `src-tauri/tests/common/mod.rs`.

**Spec:** `docs/superpowers/specs/2026-09-02-craft-ontology-design.md` (scenario 5, "The judge", Layer 3, Acceptance), amended by Task 5 of this plan. The advice this plan follows is the Codex answer of 2026-09-03: grade the decision not the hedging, gate at temperature zero, report at default temperature, never a paired judge.

/// The stance of one run, or `None` when the run never earned one: no note

fn decision(run: &Run) -> Stance {

// The gate. One run per arm at temperature 0. The two arms differ only in
// the GOAL line, so a goal-blind model that is deterministic at 0 gives the
// same answer twice and fails; the false-pass rate of that model is zero,
// and no unanimity across noisy samples is needed. The test asserts that
// the decisions differ, never which way: naming the expected direction
// would be a genre fact, and this repo holds none. A model that is still
// nondeterministic at 0 shows up here as a flaky gate; record that as a
// fact about the model in docs/manual-verification.md rather than loosen
// the assertion.
#[tokio::test]
async fn the_goal_changes_the_advice() {
    let garage = run_once(&CHORDS_GARAGE, Some(0.0)).await;
    let techno = run_once(&CHORDS_TECHNO, Some(0.0)).await;
    let report = format!(
        "\n\n=== garage arm ==={}\n=== techno arm ==={}",
        report_line(0, &garage),
        report_line(0, &techno)
    );
    let errors: Vec<&str> =
        [&garage, &techno].iter().filter_map(|r| r.infra_error.as_deref()).collect();
    assert!(errors.is_empty(), "infrastructure error on the goal gate: {errors:?}{report}");

    let g = decision(&garage);
    let t = decision(&techno);
    let verdict = if g == Stance::None {
        "under the garage goal, no decision grounded in the notes and tied to the goal"
    } else if t == Stance::None {
        "under the techno goal, no decision grounded in the notes and tied to the goal"
    } else if g == t {
        "the goal should change the decision; both arms decided the same way"
    } else {
        return;
    };
    panic!("{verdict}\n\ngarage: {g:?}\ntechno: {t:?}{report}");
